# Ablations

Every config here is the fiducial model
(`research/unit_test_variations/fourth_inloop_shearnet_d4_2drope`) with a small,
named set of keys changed. They are **generated**, not hand-written:

```
python research/ablations/generate_configs.py           # rewrite them all
python research/ablations/generate_configs.py --check   # verify, write nothing
```

Editing a config by hand will be undone by the next regeneration and is caught
by `tests/test_ablation_configs.py`. Change the fiducial, or the arm's entry in
`generate_configs.py`, and re-run.

Each generated file opens with a header giving the exact keys that changed, why
the arm exists, and anything you need to know before trusting its number.

## Submitting

`sub.sh` accepts a tier path directly:

```
cd research/unit_test_variations
./sub.sh tier1/no_psf_response
./sub.sh tier3/no_isotropy
./sub.sh first                      # a unit-test rung
./sub.sh tier2/06_d4_equivariant --no-train    # evaluate an existing checkpoint
```

## Set `catalog_level: summary` on the arms

The arms inherit `catalog_level: paper` from the fiducial, which writes every
per-object column in float32 — a few hundred MB. An ablation row reports four
scalars — m1, c2, |alpha| and the shape noise — and every one of them is in
`SUMMARY`/`LEAKSUM`. Setting `summary` takes each arm's output from ~800 MB to
~25 kB. Across the 24 arms here that is the difference between 19 GB and
600 kB, and it is the only size lever that matters: `paper` is a dtype change
and buys 2x, no more.

Do it in `generate_configs.py` (add `"eval.evaluate.catalog_level": "summary"`
to the tier deltas) rather than per file, so it survives regeneration.

Keep `paper` for the fiducial and for the four unit-test rungs: those are the
runs whose per-object columns the figures are built from.

## What is here

| tier | arms | what it establishes |
|---|---|---|
| 1 | 1 | the PSF-response penalty, the paper's central claim |
| 2 | 8 | the architecture ladder, galaxy-only up to the fiducial |
| 3 | 7 | each response objective removed from the fiducial |
| 4 | 8 | backbone schedule, training transforms, loss function |

The dataset ladder (UT1–UT4) lives in `research/unit_tests/` and is generated by
the same script: those four vary the *simulation* and hold the model fixed,
which is what makes Table 1 readable down a column.

### Tier 2 is cumulative

Rungs 1–8 each add one component to the rung above, so a row differs from the
*fiducial* in several keys while differing from its *predecessor* in one. Read
the table by adjacent differences. Rungs 1–6 also have no `train.response`
block and use `generation: upfront`, because the response penalties are only
defined once the renderer is inside the autodiff graph — that is what "before
in-loop rendering" means, not an extra variable.

### One arm is documented but not generated

`tier4/spatial_dropout`. `model.dropout` reaches only a `research_backed`
branch; on the fiducial `shearnet-d4` backbone it is silently ignored, so the
arm would train a network identical to the fiducial and report a spurious null.
It needs dropout plumbed into `_ShearNetD4Backbone` first. It is listed in
`generate_configs.BLOCKED` so it cannot be quietly forgotten.

### Two things to check against the paper before writing the table

- **EMA and input standardization are ON in the fiducial.** The appendix table
  lists them as additions to a baseline, so those rows are *removals* here and
  the signs need to match.
- **`orbit_k` is 4 in the fiducial**, so `tier3/orbit_k2` is the ablation. The
  table's wording already agrees; the older configs did not.

## Cost

Every arm is a full training on 3×10⁵ galaxies. Sizing the evaluations against
the fiducial's `m_err` before launching 24 of them is worth the one run it
costs — the arms only need enough precision to rank, and `component: 0` plus
`shape_noise_cancel: 2` cuts an evaluation substantially where that is enough.
